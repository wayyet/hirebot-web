雇佣端 UX 文档 V4

文档目的：
基于《01-产品设计备忘录》《03-雇佣端详细需求规格说明书》与现有雇佣端原型，对雇佣端的页面级 UX 设计、角色化信息架构、关键流程和跳转关系进行重写与整理，形成一份更便于产品、交互、UI、研发、测试协同使用的版本。

适用对象：
产品、交互、UI、前后端研发、测试

文档说明：
1. 本文以需求规格为准，对原型中未完整覆盖的页面、角色差异和流程回退做结构化补齐。
2. 本版按最新讨论结果，移除“工作台”模块与全部反馈链路。
3. 本版将“团队数字员工”和“部门可用”统一为一个模块名：`部门数字员工`。
4. 正式生产链路以“Web 完成雇佣、评估、配置与管理，飞书完成一对一使用”为边界，不将站内聊天视为正式工作入口。


1. 设计目标与原则

1.1 设计目标
雇佣端需要同时满足两类目标：
1. 让部门长可以基于模板完成部门版数字员工的完整雇佣流程，并持续查看团队内数字员工的状态变化。
2. 让普通成员可以从部门已上岗的数字员工中快速复制出自己的个人分身，并立即开始使用。

因此，系统必须同时支持“完整雇佣流程”和“极简复制流程”，但不能把两类流程混在一起。

1.2 开箱即用
1. 普通成员复制数字员工时，路径必须压缩到最少步骤。
2. 普通成员不进入模板池，不进入六步雇佣流程，不进入雇佣教练对话。
3. 普通成员看到的核心路径应始终是：
部门数字员工 -> 设置个人身份 -> 上岗使用
4. 所有技术概念都由系统翻译为业务语言，用户不直接操作 manifest、ontology、skill、cli 等技术对象。

1.3 严格门槛
1. 部门版与私有分支都必须经过 AI 评估与人工评估，不能绕过门槛直接上岗。
2. 评估失败后允许回退，但不允许以“跳过评估”的形式上线。
3. 上岗前必须显式完成飞书身份配置。

1.4 边界清晰
1. Web 端负责雇佣、评估、配置与管理。
2. 正式使用链路发生在飞书一对一私聊，不在 Web 端进行主生产对话。
3. 原型中的站内聊天如继续保留，建议降级为“历史会话 / 调试预览”，而不是正式入口。

1.5 隐私优先
1. 部门长可以查看团队数字员工的状态、配置与元数据，但不能查看下属与数字员工的具体私聊内容。
2. 私有分支仅创建者本人可见、可评估、可放弃。
3. 所有页面字段展示都必须遵循：
租户隔离 + 用户隔离 + 角色隔离

1.6 一对一使用
1. 数字员工仅支持在飞书私聊中使用。
2. 不提供群聊入口，不做兜底开放。
3. 所有文案与操作路径都要持续强化“去飞书使用”的心智。

1.7 文案统一
1. 面向用户的主表达统一使用“雇佣”。
2. 推荐统一文案：
雇佣、继续雇佣、重新雇佣、去飞书使用、部门数字员工、我的数字员工
3. “基于模板调教”等说法仅用于内部流程说明，不作为前台主文案。


2. 角色、对象与状态

2.1 角色定义
部门长：
负责查看企业模板池，发起部门版雇佣，查看部门数字员工，并对团队内处于评估中的实例继续处理直至上岗。

普通成员：
负责查看部门数字员工中的已上岗实例，复制出个人分身，并在飞书中使用自己的数字员工。

分身 Owner：
指个人分身的拥有者。只有 owner 可以为自己的 personal_clone 创建私有分支。

2.2 核心对象
模板 template：
雇佣起点，只能被浏览和选择，不能在雇佣端直接生产或派生新模板。

部门版 department：
由部门长基于模板创建，面向本部门复用。
前台展示文案建议为：部门员工。

个人分身 personal_clone：
由用户基于部门版复制得到，独立使用，拥有自己的对外身份配置。
前台展示文案建议为：我的分身。

私有分支 private_branch：
由 personal_clone 的 owner 基于现有分身进行个性化定制得到，仅 owner 可见。
前台展示文案建议为：私人定制。

2.3 状态定义
hired：
已启动流程，尚未进入评估。

interning_ai：
AI 评估中。

interning_human：
人工评估中。

live：
已上岗，可在飞书私聊中使用。

failed：
评估失败，等待进入 Review 决定回退位置。

retired：
已退役，只读。

2.4 状态与模块映射
`部门数字员工` 采用统一模块名，但按角色展示不同内容：

部门长视图：
1. 已雇佣：对应 hired
2. 待实习：包含两个子标签
AI 评估，对应 interning_ai
人工评估，对应 interning_human
3. 已上岗：对应 live

普通成员视图：
1. 只显示已上岗
2. 只展示当前部门可复制的 live 部门版

补充说明：
1. failed 不单独做一级模块，优先通过实例详情页和 Review 页承接。
2. retired 不进入部门主列表，优先放在“我的数字员工”中作为历史状态承接。

2.5 状态与按钮联动
live：
显示“去飞书使用”，并根据类型显示详情动作。

interning_ai / interning_human：
显示“查看评估进度”。

failed：
显示“查看评估报告”“继续雇佣”。

retired：
显示“查看历史”“重新复制”或“重新雇佣”。

2.6 权限边界
1. 部门长可以查看本部门范围内的部门版状态、评估进度和上岗情况。
2. 部门长的“我的数字员工”仅展示其本人拥有的“我的分身”和“私人定制”。
3. 普通成员在“部门数字员工”中只能看本部门 live 的“部门员工”，以及自己的“我的分身”和“私人定制”。
4. 非 owner 不展示会话历史入口。
5. 私有分支详情仅 owner 可见。


3. 信息架构

3.1 顶层模块
部门长模块：
1. 企业模板池
2. 部门数字员工
3. 我的数字员工

普通成员模块：
1. 部门数字员工
2. 我的数字员工

3.2 页面分类
列表 / 模块页：
1. 企业模板池
2. 部门数字员工
3. 我的数字员工

详情页：
1. 数字员工详情
2. 模板详情

流程页：
1. 部门版雇佣页
2. AI 评估页
3. 人工评估页
4. Review 页
5. 飞书身份配置与上岗页
6. 分身复制向导
7. 私有分支定制页

共享组件：
1. 飞书使用引导弹层

3.3 核心入口策略
1. 部门长从“企业模板池”进入完整雇佣流程。
2. 部门长从“部门数字员工”管理本部门的 hired、interning_ai、interning_human、live 状态实例。
3. 部门长从“我的数字员工”管理自己拥有的“我的分身”和“私人定制”。
4. 普通成员从“部门数字员工”的已上岗视图进入三步复制流程。
5. 数字员工详情页承担所有状态承接与动作分发。


4. 页面清单与详细说明

4.1 企业模板池
页面目标：
供部门长浏览企业模板和全局模板，并选择一个模板开始雇佣部门版。

适用角色：
部门长

进入条件：
从顶层模块进入

核心模块：
1. 搜索区
2. 模板列表区

卡片字段：
1. 模板名称
2. 模板来源：全局通用 / 企业专属
3. 场景简介
4. 适用部门
5. 使用次数

关键规则：
1. 不提供“派生新模板”“编辑模板源码”等入口。
2. 不提供新增模板入口，部门长只能使用已有模板发起部门版雇佣。
3. 用户只能基于模板创建部门版，不能在雇佣端生产模板。

4.2 部门数字员工
页面目标：
以统一模块名承接部门级数字员工资产，但根据角色提供不同视图。

适用角色：
部门长、普通成员

进入条件：
从顶层模块进入

部门长视图：
1. 一级标签：
已雇佣、待实习、已上岗
2. 二级标签：
待实习下拆分为 AI 评估、人工评估
3. 列表区：
按卡片展示团队内数字员工

普通成员视图：
1. 不显示“已雇佣”“待实习”
2. 仅显示“已上岗”结果集
3. 本质上是本部门可复制的 live 部门版列表

卡片字段建议：
1. 对外名称与头像
2. 当前状态或当前阶段
3. 最近更新时间
4. 查看详情

动作规则：
部门长 / 全部状态：主动作统一为查看详情
普通成员 / 已上岗：主动作统一为查看详情

关键规则：
1. 这是部门级数字员工的统一主入口。
2. 卡片主动作统一为查看详情，由详情页承接不同状态下的下一步按钮。
3. “同名模块，不同角色看不同状态范围”是本页核心设计。
4. failed 实例不新增一级标签，通过实例详情与 Review 页回退承接。
5. 该页不承接个人私有分支的详细管理，个人资产统一去“我的数字员工”。

4.3 我的数字员工
页面目标：
按个人视角管理当前用户本人拥有的数字员工实例。

适用角色：
部门长、普通成员

进入条件：
从顶层模块进入

页面范围：
1. 仅显示当前用户本人拥有的“我的分身”和“私人定制”。
2. 不在此页展示整个团队的“部门员工”列表。

核心模块：
1. 筛选条：状态、实例类型、来源模板、最近活跃时间
2. 列表区：卡片化展示数字员工
3. 汇总区：实例总数、状态分布、异常实例数

卡片字段建议：
1. 对外名称与头像
2. 实例类型标签：部门员工 / 我的分身 / 私人定制
3. 当前状态标签
4. 来源关系
5. 最近活跃时间
6. 最近一次评估结果或失败状态

动作规则：
live：详情、去飞书使用
interning_ai / interning_human：查看评估进度
failed：查看报告、继续雇佣
retired：查看历史、重新复制

4.4 数字员工详情
页面目标：
承接单个实例的状态、来源、身份、运行情况与后续动作。

适用角色：
全体用户

进入条件：
从列表页、评估完成页进入

核心模块：
1. 基本信息区：名称、头像、类型、状态、所属部门、owner
2. 来源关系区：模板 -> 部门员工 -> 我的分身 -> 私人定制
3. 能力简介区：业务可读能力标签，不展示底层文件
4. 飞书身份区：display_name、avatar、description、bot 状态
5. 运行状态区：最近活跃时间、累计任务数、最近错误
6. 操作区：根据类型与状态显示主动作

主按钮建议：
部门员工 + hired：继续雇佣
部门员工 + interning_ai：查看 AI 评估
部门员工 + interning_human：查看人工评估
部门员工 + live + 部门长：重新雇佣、复制一个给自己
部门员工 + live + 普通成员：创建分身
我的分身 + live：去飞书使用、创建私有分支、退役
failed：查看评估报告、继续雇佣
retired：查看历史、重新复制 / 重新雇佣

关键规则：
1. 非 owner 不显示会话历史入口。
2. 部门长查看团队内实例时，只展示元数据、状态和配置，不展示私聊明细。
3. 详情页应根据当前实例状态提供进入下一步环节的主按钮。
4. 私有分支详情仅 owner 可见。

4.5 模板详情
页面目标：
帮助部门长判断模板是否适合当前部门，并作为唯一的部门版雇佣起点。

适用角色：
部门长

进入条件：
从企业模板池卡片进入

核心模块：
1. 模板概览：名称、来源、适用场景、适配度提示
2. 业务描述
3. 能力清单
4. 使用情况：已生成部门版数、已被复制次数
5. 主动作区：雇佣

关键规则：
1. 从此页发起雇佣时要带入 template_id。
2. 关闭或返回时保留模板池搜索关键词和滚动位置。

4.6 部门版雇佣页
页面目标：
通过 digital_employee_discovery 引导部门长完成完整六步雇佣流程。

适用角色：
部门长

进入条件：
从模板详情点击“雇佣”进入

页面结构建议：
1. 顶部步骤条：
场景匹配 -> 差距挖掘 -> 人设生成 -> 知识生成 -> 能力生成 -> 外部对接
2. 左侧会话区：承接雇佣教练对话、逐步提问、上传提醒、确认结果
3. 右侧产物区：实时展示已确认场景、知识缺口、能力清单、边界条件、材料状态，并按步骤持续沉淀中间产物
4. 附件区：在知识生成阶段展示上传与解析状态
5. 测试用例沉淀区：收集真实任务样例，供后续评估使用
6. 底部操作区：上一步、保存退出、下一步、确认当前结果

六步重点：
1. 场景匹配：目标场景、目标用户、主要任务、模板适配度
2. 差距挖掘：知识缺口、能力缺口、外部系统、禁做边界
3. 人设生成：角色定位、语气风格、不可越界事项
4. 知识生成：资料上传、解析结果、知识结构预览、缺失提醒
5. 能力生成：能力清单、可做 / 不可做边界校验
6. 外部对接：系统清单、认证信息采集、连通性测试结果

关键规则：
1. 用户不直接操作底层技术对象。
2. 每一步都必须有“已确认结果”视图，减少遗失感。
3. 六步流程按步骤生成并确认中间产物，不是最后一次性生成完整实例包。
4. 支持保存退出，后续从“部门数字员工 > 已雇佣”恢复。
5. 六步全部确认后，系统将已沉淀的中间产物汇总为完整实例配置，再进入 AI 评估。

4.7 AI 评估页
页面目标：
作为独立功能承接 AI 自动化评估，展示标准检查、测试执行、判分与训练建议结果。

适用角色：
部门长、私有分支用户

进入条件：
雇佣配置完成后自动进入，或从列表页查看。
进入 AI 评估时，输入对象应为六步流程全部确认后的完整实例配置，而不是单一步骤的局部结果。

核心模块：
1. 评估进度区：当前阶段、已完成项、预计剩余时间
2. 标准检查区：结构完整性、边界配置、资料完整度、对接校验
3. 测试结果区：场景用例、得分、失败案例、风险说明
4. 训练建议区：对下一步人工评估的重点提示
5. 结论区：通过 / 不通过 / 待补充

占位实现要求：
1. 可先用占位标签页和示意数据承接页面结构。
2. 但必须保留“进入人工评估”的主按钮与“去 Review”的失败出口。

关键规则：
1. AI 评估通过后才允许进入人工评估。
2. AI 评估不直接完成上岗决策。

4.8 人工评估页
页面目标：
承接真实用户评估，在场景轮次会话中完成最终上岗判断。

适用角色：
部门长、私有分支 owner

进入条件：
AI 评估通过后进入

核心模块：
1. 场景任务区：按轮次展示测试任务
2. 会话预览区：查看思考链路、工具调用、对话详情
3. 综合报告区：汇总所有场景后的整体判断
4. 上岗操作区：确认上岗、修改配置后重评、强制上岗

占位实现要求：
1. HTML 阶段可先以占位会话、场景卡片、综合报告承接流程。
2. 必须预留“场景判断”和“综合报告”的稳定视觉位置。
3. 主流程按钮至少覆盖：
人工评估通过 -> 配置飞书上岗
人工评估不通过 -> Review / 返回雇佣

关键规则：
1. 用户不能跳过人工评估直接上岗。
2. 人工评估评的是目标数字员工，不应表现成继续与 AI 评估专家对话。
3. 若存在不合格或未评估场景，强制上岗必须带二次确认。

4.9 Review 页
页面目标：
在评估失败后帮助用户决定回退到哪个工位继续雇佣配置。

适用角色：
部门长、私有分支用户

进入条件：
AI 评估或人工评估失败

核心模块：
1. 失败摘要区：总分、低分维度、关键失败案例
2. 回退入口区：
场景匹配、差距挖掘、人设生成、知识生成、能力生成、外部对接
3. 保留说明区：说明已上传原料保留、生成结果将被重算
4. 风险提示区：连续失败次数与系统建议
5. 放弃区：仅私有分支显示“放弃私有分支”

关键规则：
1. 部门版不提供“放弃本次雇佣”的主出口，只能继续完成或暂存。
2. 私有分支允许放弃，且不能影响原分身继续可用。

4.10 飞书身份配置与上岗
页面目标：
在上岗前完成飞书对外身份配置、bot 注册和运行时启动。

适用角色：
全体用户

进入条件：
人工评估通过，或分身复制进入绑定阶段

核心模块：
1. 飞书预览区：头像、名称、描述
2. 表单区：display_name、display_avatar、display_description
3. 校验区：同一 owner 下名称唯一、必填项校验
4. 上岗进度区：bot 注册、身份写入、沙箱启动、状态切换

关键规则：
1. display_name 必填。
2. 修改对外身份不等于修改人设，不应触发重新评估。
3. 分身与部门版都在此完成“看起来是谁”的配置。

完成后：
成功 -> 返回数字员工详情并展示上岗成功
失败 -> 留在当前页展示错误原因，允许重试

4.11 分身复制向导
页面目标：
用最少步骤完成普通成员创建个人分身，也就是从部门员工到个人分身的复制与上岗。

适用角色：
普通成员，也可供部门长复制给自己

进入条件：
从“部门数字员工”的已上岗视图或部门员工详情点击“创建分身”

建议采用三步横向向导：
1. 确认复制：展示母版简介与“复制后独立”说明
2. 配置个人对外身份：复用飞书身份组件
3. 绑定并上岗：注册 bot、启动运行时、显示完成状态

页面要求：
1. 不出现雇佣教练对话。
2. 总操作步数不超过 3 步。
3. 明确说明“不进入双阶段评估”。
4. 只保留当前步骤必要字段，不引入复杂可选项。

4.12 私有分支定制页
页面目标：
在不破坏原分身的前提下完成个性化定制。

适用角色：
分身 owner

进入条件：
从 personal_clone 详情点击“创建私有分支”

页面结构建议：
1. 原分身信息区：展示来源、最近使用情况
2. 差异目标区：先让用户说清楚“想改什么”
3. 工位选择区：人设 / 知识 / 能力 / 外部对接
4. 简化版训练区：只围绕已选工位追问
5. 继承说明区：未改动部分继续沿用原分身
6. 评估与切换区：进入 AI 评估、人工自评、通过后切换路由

关键规则：
1. 私有分支不能再创建二级分支。
2. 评估通过后不新增飞书联系人，而是替换原 bot 的底层路由。
3. 定制失败可放弃，不影响原分身继续可用。


5. 关键流程

5.1 部门长主流程
企业模板池
-> 模板详情
-> 部门版雇佣页
-> AI 评估页
-> 人工评估页
-> 飞书身份配置与上岗
-> 部门数字员工（已上岗）
-> 数字员工详情

续办逻辑：
1. 部门数字员工 / 已雇佣 -> 数字员工详情 -> 继续雇佣 -> 部门版雇佣页
2. 部门数字员工 / 待实习 / AI 评估 -> 数字员工详情 -> 查看 AI 评估 -> AI 评估页
3. 部门数字员工 / 待实习 / 人工评估 -> 数字员工详情 -> 查看人工评估 -> 人工评估页
4. 部门数字员工 / 已上岗 -> 数字员工详情

失败回路：
AI 评估失败或人工评估失败
-> Review 页
-> 回退到对应雇佣工位继续处理

5.2 普通成员主流程
部门数字员工（已上岗视图）
-> 数字员工详情
-> 分身复制向导
-> 飞书身份配置与上岗
-> 我的数字员工
-> 数字员工详情
-> 去飞书使用

5.3 私有分支流程
数字员工详情
-> 私有分支定制页
-> AI 评估页
-> 人工评估页
-> 路由切换
-> 私有分支详情

失败回路：
AI / 人工评估失败
-> Review 页
-> 回退定制工位
或
-> 放弃私有分支
-> 返回原分身详情
