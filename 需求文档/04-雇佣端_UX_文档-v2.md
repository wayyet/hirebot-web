# 雇佣端 UX 文档 V7

**文档目的：**
基于《02-0 雇佣端完整需求规格说明书-v2（v4.0）》，对雇佣端的页面级 UX 设计、角色化信息架构、关键流程和跳转关系进行全面更新，适配四阶段装配流程、站内对话主渠道、多平台 IM 接入等 v4.0 新增功能。

**适用对象：**
产品、交互、UI、前后端研发、测试

**文档说明：**

1. 以《需求规格说明书 v4.0》为权威依据，与原型中未完整覆盖的页面做补齐。
2. v7 核心变更：
   - 雇佣流程由六步 discovery 调整为**四阶段装配**（上传资料 → 补齐技能 → 配置外部系统 → 生成实例包）
   - **站内对话**升级为上岗后的默认主渠道，无需任何配置即可使用
   - IM 接入扩展为飞书 / 钉钉 / 企微三平台并行，改为完全可选
   - 新增页面：站内对话页（主要对话渠道）、多平台 IM 配置页
   - 更新待办区（右侧面板）的分阶段渲染规则

---

## 1. 设计目标与原则

### 1.1 设计目标

雇佣端需要同时满足三类目标：

1. 让部门长可以基于模板完成部门版数字员工的完整雇佣流程（四阶段装配 + 双阶段评估），并持续查看团队内数字员工的状态变化。
2. 让部门长和普通成员可以从已有部门员工**快速复制出个人分身**，完成后**立即在平台内通过站内对话开始使用**。
3. 让分身 owner 可以按需接入 IM（飞书 / 钉钉 / 企微），或创建私有分支进行个性化定制。

因此，系统必须同时支持"完整雇佣流程"、"极简分身复制流程"和"私有分支定制流程"，但不能把三类流程混在一起。

### 1.2 开箱即用

1. 普通成员复制数字员工时，路径必须压缩到最少步骤（目标：≤ 3 步）。
2. 普通成员不进入模板池，不进入四阶段装配流程，不进入雇佣教练对话。
3. 普通成员看到的核心路径应始终是：

   `部门数字员工 → 创建分身 → 设置显示信息 → 上岗 → 站内对话立即可用`

4. IM 接入是**个人分身层面的可选操作**，在分身卡片上提供入口，不阻塞上岗流程。
5. 所有技术概念都由系统翻译为业务语言，用户不直接操作 manifest、ontology、skill 等技术对象。

### 1.3 严格门槛

1. 部门版雇佣与私有分支都必须经过双阶段评估（AI 评估 + 人工评估），不能绕过。
2. 评估失败后允许回退，但不允许以"跳过评估"的形式发布上线。
3. 分身复制（personal_clone）**继承**母实例的评估结果，无需重走评估，直接上岗。
4. 部门员工发布后不配置 IM；IM 接入是个人分身层面的可选操作。

### 1.4 边界清晰

1. Web 端负责雇佣、评估、配置与管理。
2. 数字员工上岗后支持两类主动发起对话的方式：
   - **站内对话（主要渠道）**：在 Web 端内嵌界面直接对话，上岗即可用，无需任何额外配置。
   - **拉起 IM（可选渠道）**：从 Web 端点击"去 {平台名}"按钮，跳转到对应 IM 应用并进入与员工机器人的私聊，需先完成 IM 注册。
3. 两种方式不互斥，底层共用同一运行时沙箱，对话上下文各自独立。

### 1.5 隐私优先

1. 部门长可以查看团队数字员工的状态、配置与元数据，但**不能查看**下属与数字员工的具体私聊内容。
2. 私有分支仅创建者本人可见、可评估、可废弃。
3. 所有页面字段展示都必须遵循：`租户隔离 + 用户隔离 + 角色隔离`

### 1.6 多渠道使用

1. 数字员工支持两类使用渠道：**站内对话（默认）** 和 **IM 接入（可选）**。
2. 站内对话：上岗即可用，无需额外配置，是 MVP 阶段的主要对话入口。
3. IM 接入：支持飞书、钉钉、企微，每个平台独立配置，同一员工可同时接入多个平台。
4. IM 接入后仅支持一对一私聊，不提供群聊入口。
5. 站内对话与 IM 渠道的对话历史**独立存储**，不互通。

### 1.7 文案统一

1. 面向用户的主表达统一使用"雇佣"。
2. 推荐统一文案：

   雇佣、继续雇佣、重新雇佣、开始对话、配置 IM、去飞书使用、部门数字员工、我的数字员工

3. 分身创建动作面向用户使用"创建分身"，强调"上岗即可对话，无需评估"。

## 2. 角色、对象与状态

### 2.1 角色定义

- **部门长：** 负责查看企业模板池，发起部门版雇佣，管理部门数字员工，可查看全部状态实例并推动至上岗。同时可以创建个人分身。
- **普通成员：** 负责查看部门数字员工中的已上岗实例，复制出个人分身，**通过站内对话直接使用**，并可按需接入 IM。
- **分身 Owner：** 指个人分身的拥有者，只有 owner 可以为自己的 personal_clone 创建私有分支、配置 IM、开始对话。

### 2.2 核心对象

- **模板 template：** 雇佣起点，只能被浏览和选择，不能在雇佣端直接生产或派生新模板。
- **部门员工 department：** 由部门长基于模板走完整四阶段装配 + 双阶段评估创建，面向本部门复用。**不配置 IM**。
- **我的分身 personal_clone：** 由用户基于部门员工快照复制得到，独立使用，继承父实例评估结果直接上岗，可配置 IM。
- **私人定制 private_branch：** 由 personal_clone 的 owner 基于现有分身进行个性化定制得到，走完整双阶段评估，仅 owner 可见，拥有独立 IM 配置。

### 2.3 状态定义

| 状态 | 说明 | 可见性 |
| --- | --- | --- |
| `hired` | 已启动流程，四阶段装配进行中。 | 仅雇佣者 |
| `interning_ai` | AI 评估中（双沙箱模式）。 | 仅雇佣者 |
| `interning_human` | 人工评估中，等待部门长/用户自评。 | 仅雇佣者 |
| `live` | 已上岗，站内对话立即可用，可按需配置 IM。 | 部门员工：全部门；分身/私人定制：仅 owner |
| `error` | 沙箱连续 3 次冷启动失败，暂时不可用。 | 仅 owner + 平台运维 |
| `failed` | 评估失败，等待进入 Review 决定回退位置。 | 仅雇佣者 |
| `retired` | 已退役，只读历史。 | 仅 owner |

### 2.4 状态与模块映射

`部门数字员工` 采用统一模块名，但按角色展示不同内容：

**部门长视图（部门数字员工）：**

1. 已雇佣：对应 `hired`
2. 待实习：包含两个子标签
   - AI 评估中：对应 `interning_ai`
   - 人工评估中：对应 `interning_human`
3. 已上岗：对应 `live`
4. 失败/异常：`failed` 和 `error` 通过详情页承接

**普通成员视图（部门数字员工）：**

1. 只显示已上岗（`live`）的部门员工
2. 提供"创建分身"入口

**补充说明：**

1. `failed` 不单独做一级标签，通过实例详情页和 Review 页承接。
2. `retired` 不进入部门主列表，在"我的数字员工"中作为历史状态承接。
3. `error` 状态下员工卡片显示异常提示，但不阻塞其他员工使用。

### 2.5 状态与按钮联动

| 状态 + 类型 + 角色 | 主按钮 | 次要动作 |
| --- | --- | --- |
| `live`（部门员工 + 部门长） | — | 创建分身、重新雇佣 |
| `live`（部门员工 + 普通成员） | 创建分身 | — |
| `live`（我的分身 / 私人定制 + owner） | **开始对话** | 去 IM、配置 IM、创建私有分支、退役 |
| `hired` | 继续雇佣 | — |
| `interning_ai` | 查看 AI 评估进度 | — |
| `interning_human` | 进入人工评估 | — |
| `failed` | 查看评估报告、继续雇佣 | — |
| `error` | 查看错误详情 | 退役 |
| `retired` | 查看历史 | 重新复制 / 重新雇佣 |

### 2.6 权限边界

1. 部门长可以查看本部门所有部门员工的状态、评估进度和上岗情况。
2. 部门长的"我的数字员工"仅展示其本人拥有的"我的分身"和"私人定制"。
3. 普通成员在"部门数字员工"中只能看本部门 `live` 的"部门员工"。
4. 非 owner 不展示"开始对话"入口和会话历史入口。
5. 私有分支详情仅 owner 可见。

## 3. 信息架构

### 3.1 顶层模块

**部门长模块：**

1. 企业模板池
2. 部门数字员工
3. 我的数字员工

**普通成员模块：**

1. 部门数字员工
2. 我的数字员工

### 3.2 页面分类

**列表 / 模块页：**

1. 企业模板池
2. 部门数字员工
3. 我的数字员工

**详情页：**

1. 数字员工详情
2. 模板详情

**流程页：**

1. 部门版雇佣页（四阶段装配：左侧会话区 + 右侧待办区）
2. AI 评估页
3. 人工评估页
4. Review 页（评估失败后回退）
5. 上岗确认页（人工评估通过后发布）
6. 分身复制向导（三步：确认复制 → 设置显示信息 → 上岗）
7. 私有分支定制页（简化模式雇佣教练 + 双阶段评估）
8. IM 配置页（多平台：飞书 / 钉钉 / 企微）

**对话页：**

1. **站内对话页（主要对话渠道，上岗即可用）**

**共享组件：**

1. IM 配置引导弹层（多平台）
2. AI 评估进度卡片
3. 分身数量上限提示

### 3.3 核心入口策略

1. 部门长从"企业模板池"进入完整四阶段装配流程。
2. 部门长从"部门数字员工"管理本部门所有状态实例。
3. 部门长和普通成员从"部门数字员工"的已上岗员工进入分身复制向导。
4. 用户从"我的数字员工"的员工卡片**直接进入站内对话**（主要使用入口）。
5. 用户从员工卡片或详情页进入 IM 配置，配置完成后可点击"去 {平台名}"拉起 IM。
6. 数字员工详情页承担所有状态承接与动作分发。

## 4. 页面清单与详细说明

### 4.1 企业模板池

- **页面目标：** 供部门长浏览企业模板和全局模板，并选择一个模板开始雇佣部门版。
- **适用角色：** 部门长
- **进入条件：** 从顶层模块导航进入

**核心模块：**

1. 搜索区：关键词搜索，不提供其他筛选器
2. 模板列表区：卡片化展示

**卡片字段：**

1. 模板名称与头像
2. 模板来源：全局通用 / 企业专属
3. 场景简介
4. 使用次数（已生成部门版数）

**关键规则：**

1. 不提供"派生新模板"、"编辑模板源码"等入口。
2. 部门长只能基于模板创建部门版，不能在雇佣端生产模板。
3. 从模板卡片进入详情，详情页提供"雇佣"按钮作为唯一起点。

---

### 4.2 部门数字员工

- **页面目标：** 以统一模块名承接部门级数字员工资产，但根据角色提供不同视图。
- **适用角色：** 部门长、普通成员
- **进入条件：** 从顶层模块导航进入

**部门长视图：**

1. 一级标签：已雇佣、待实习、已上岗
2. 二级标签：待实习下拆分为 AI 评估中、人工评估中
3. 列表区：卡片化展示团队内数字员工

**普通成员视图：**

1. 仅显示"已上岗"
2. 本质上是本部门可复制的 `live` 部门员工列表

**卡片字段：**

1. 对外名称与头像
2. 当前状态或阶段标签
3. 来源模板名称
4. 最近更新时间

**动作规则：**

| 角色 | 状态 | 主动作 | 次要动作 |
| --- | --- | --- | --- |
| 部门长 | `hired` | 继续雇佣 | — |
| 部门长 | `interning_ai` | 查看 AI 评估 | — |
| 部门长 | `interning_human` | 进入人工评估 | — |
| 部门长 | `live` | 查看详情 | 创建分身、重新雇佣 |
| 部门长 | `failed` | 查看报告 | 继续雇佣 |
| 普通成员 | `live` | 创建分身 | 查看详情 |

**关键规则：**

1. `failed` 实例不新增一级标签，通过卡片按钮进入详情 / Review 页承接。
2. 该页不承接个人私有分身的详细管理，个人资产统一在"我的数字员工"。
3. 分身数量达上限（10 个）时，"创建分身"按钮置灰并提示"已达分身上限（N/10）"。

### 4.3 我的数字员工

- **页面目标：** 按个人视角管理当前用户本人拥有的分身和私人定制，提供站内对话快速入口。
- **适用角色：** 部门长、普通成员
- **进入条件：** 从顶层模块导航进入

**页面范围：**

1. 仅显示当前用户本人拥有的"我的分身"（personal_clone）和"私人定制"（private_branch）。
2. 不在此页展示整个团队的"部门员工"列表。

**核心模块：**

1. 筛选条：实例类型（我的分身 / 私人定制）、状态、来源模板
2. 列表区：卡片化展示

**卡片字段：**

1. 对外名称与头像
2. 实例类型标签：我的分身 / 私人定制
3. 当前状态标签
4. 来源部门员工名称
5. 最近活跃时间
6. IM 接入状态图标：飞书 / 钉钉 / 企微（已配置绿色、未配置灰色、异常红色）

**动作规则：**

| 状态 | 主按钮 | 次要动作 |
| --- | --- | --- |
| `live` | **开始对话**（进入站内对话页） | 去 IM（已注册时显示）、配置 IM、创建私有分支、退役 |
| `interning_ai` | 查看 AI 评估进度 | — |
| `interning_human` | 进入人工评估 | — |
| `failed` | 查看报告、继续雇佣 | — |
| `error` | 查看错误详情 | 退役 |
| `retired` | 查看历史 | 重新复制 |

**关键规则：**

1. `live` 状态卡片的主按钮统一为**"开始对话"**，点击直接进入站内对话页，不跳转到详情页。
2. **"去 IM"按钮**：至少有一个 IM 平台 `status=active` 时显示；多平台已配置时弹出平台选择气泡（飞书 / 钉钉 / 企微图标列表）；仅一个时直接跳转拉起。
3. **"配置 IM"入口**：始终在卡片次要操作区可见，供用户随时进入 IM 配置页。
4. 点击"去 IM"但尚未配置任何平台时：显示提示"该员工尚未接入 IM，是否立即配置？"，提供"去配置"和"取消"。
5. `error` 状态下员工卡片显示红色异常标记，主按钮变为"查看错误详情"。

### 4.4 数字员工详情

- **页面目标：** 承接单个实例的状态、来源、身份、运行情况与后续动作。
- **适用角色：** 全体用户
- **进入条件：** 从列表页卡片进入

**核心模块：**

1. **基本信息区：** 名称、头像、实例类型标签、当前状态标签、所属部门、owner
2. **来源关系区：** 模板 → 部门员工 → 我的分身（→ 私人定制）层级展示
3. **能力简介区：** 业务可读能力标签，不展示底层技术文件
4. **IM 接入区（仅我的分身 / 私人定制显示，部门员工不显示）：**
   - 飞书 / 钉钉 / 企微三平台各自展示一行：
     - 已连接（`active`）：绿色图标 + "已连接" + "去 {平台名}" 按钮（拉起 IM）
     - 未配置（`unconfigured`）：灰色图标 + "未配置" + "配置 IM" 按钮
     - 配置异常（`error`）：红色图标 + "配置异常" + "重新配置" 按钮
5. **运行状态区：** 最近活跃时间、累计对话轮次、运行状态
6. **操作区：** 根据类型与状态显示主动作

**主按钮建议：**

| 实例类型 + 状态 + 角色 | 主按钮 | 次要按钮 |
| --- | --- | --- |
| 部门员工 + `hired` + 部门长 | 继续雇佣 | — |
| 部门员工 + `interning_ai` + 部门长 | 查看 AI 评估 | — |
| 部门员工 + `interning_human` + 部门长 | 进入人工评估 | — |
| 部门员工 + `live` + 部门长 | 创建分身 | 重新雇佣 |
| 部门员工 + `live` + 普通成员 | 创建分身 | — |
| 我的分身 + `live` + owner | **开始对话** | 创建私有分支、退役 |
| 私人定制 + `live` + owner | **开始对话** | 退役 |
| 任意 + `failed` | 查看评估报告 | 继续雇佣 |
| 任意 + `retired` | 查看历史 | 重新复制 / 重新雇佣 |

**关键规则：**

1. 非 owner 不显示"开始对话"和站内对话历史入口。
2. 部门长查看团队内实例时，只展示元数据、状态和配置，不展示私聊明细。
3. 私有分支详情仅 owner 可见。
4. 部门员工不显示 IM 接入区。

### 4.5 模板详情

- **页面目标：** 帮助部门长判断模板是否适合当前部门，作为唯一的部门版雇佣起点。
- **适用角色：** 部门长
- **进入条件：** 从企业模板池卡片进入

**核心模块：**

1. 模板概览：名称、来源（全局通用 / 企业专属）、适用场景
2. 业务描述（来自模板的 `describe.md`）
3. 能力清单（来自模板的 skill 列表）
4. 使用情况：已生成部门版数
5. 主动作区：**雇佣**

**关键规则：**

1. 从此页发起雇佣时，系统初始化四阶段装配环境（沙箱 + 待办区），带入 `template_id`。
2. 关闭或返回时保留模板池搜索关键词和滚动位置。
3. 模板源代码（config、skill 目录）不对用户可见。

### 4.6 部门版雇佣页（四阶段装配）

- **页面目标：** 通过雇佣教练与用户**并肩装配**，完成四阶段装配流程，生成完整实例包，进入 AI 评估。
- **适用角色：** 部门长
- **进入条件：** 从模板详情点击"雇佣" / 从部门员工详情点击"重新雇佣" / 从 Review 页选择回退环节

#### 4.6.2 顶部进度条

#### 4.6.3 左侧会话区

- 雇佣教练以**数字员工身份**开场，介绍自己的使命，引导用户完成当前阶段待办。
- 对话气泡区：用户消息（右对齐） + 雇佣教练回复（左对齐），支持流式输出。
- 底部输入区：文本框（Enter 发送，Shift+Enter 换行）+ 附件上传按钮。
- 附件上传按钮在**任何阶段均可见**（材料可随时上传），上传后在右侧附件区展示。

**雇佣教练开场内容（基于模板人设）：**

系统加载模板的 `IDENTITY.md` 和 `SOUL.md`，雇佣教练以该员工的身份介绍自己的工作职责、价值取向，并告知用户当前需要完成的第一个阶段待办。

---

#### 4.6.4 右侧待办区（分阶段渲染）

右侧待办区始终可见，按四阶段分组展示，**仅展示当前已解锁的阶段**。当前阶段高亮展开，已完成阶段折叠（可点击展开查看），待解锁阶段不显示。

##### 待办区 · 阶段①：上传资料

**外观：** 右侧面板展示已上传材料的附件列表。

**附件条目字段：**
- 文件名 + 文件图标
- 文件大小
- 上传时间
- 状态标签：上传中 / 已上传 / 处理中 / 已就绪

**交互：**
- 点击附件可放大预览
- 可删除已上传的附件（删除后重新上传）

**待办状态标签（每条资料待办）：**

| 状态 | 样式 | 含义 |
|---|---|---|
| 信息收集中 | 橙色标签 | 信息不足，雇佣教练引导补充 |
| 处理中 | 蓝色标签 + 旋转图标 | 信息充分，`ontology-extraction` 运行中 |
| 已完成 | 绿色标签 + 对勾 | 本体抽取完成，自动生成测试用例 |

**阶段推进条件：** 至少一条资料待办状态为"已完成"，自动解锁②阶段。

---

##### 待办区 · 阶段②：补齐技能

**外观：** 右侧面板展示 Skill 列表，分为两组：

- **模板已有 Skill**（灰色区块）：来自模板的原有技能，只读，可展开查看详情
- **新增 / 生成的 Skill**（白色区块）：本次装配过程中生成或上传的技能，可展开、可确认、可删除

**Skill 条目字段：**
- Skill 名称（英文 slug）+ 中文标签
- 用途描述（description）
- 来源标签：对话生成 / 文件上传 / 模板自带
- 状态：待确认 / 已确认 / 处理中

**展开后显示完整字段：**
- `name`：技能名称
- `description`：用途描述
- `trigger`：触发条件
- （可读版本，不显示底层代码）

**技能输入方式：**

两种并行输入模式：
1. **会话生成**：在左侧会话框描述一项技能需求，雇佣教练生成草稿并添加到右侧列表，用户逐条确认
2. **上传 Skill 文件**：右侧面板内提供"上传 Skill 文件"入口（仅此阶段显示），用户上传文件后系统解析并提取字段填入条目

**阶段推进条件：** 至少一条新增 Skill 状态为"已确认"，自动解锁③阶段。

---

##### 待办区 · 阶段③：配置外部系统

**外观：** 右侧面板展示外部系统列表，每个系统对应一行配置条目。

**系统条目字段：**
- 系统名称（如：企业微信、CRM、ERP）
- 配置状态：未配置 / 配置中 / 已完成 / 已跳过
- 【配置】按钮：点击展开填写表单

**接入类型选择：** 用户在会话中描述外部系统后，雇佣教练识别类型并在右侧创建对应条目；用户也可手动选择接入类型。支持以下四种类型，各自展示不同的配置表单：

---

**① CLI（命令行工具调用）**

用于调用本地或容器内的命令行工具。

```
接入类型：CLI
─────────────────────────────────────────────
工具名称        [填写工具的可执行名称，如 jq / ffmpeg]
描述            [这个工具做什么，何时触发调用]
调用方式        ○ 直接执行  ○ 沙箱执行
允许的参数模板  [可选；预设参数格式，如 --input {file} --output {out}]
─────────────────────────────────────────────
```

关键规则：
- 每个 CLI 工具对应一条配置条目，支持添加多条
- 调用方式选"沙箱执行"时，平台提示该工具将在隔离环境运行，不可访问宿主文件系统

---

**② MCP（Model Context Protocol 工具集）**

用于接入 MCP server 暴露的工具集合。

```
接入类型：MCP
─────────────────────────────────────────────
MCP Server 地址  [填写 server endpoint URL]
认证方式         ○ 无认证  ○ API Key  ○ OAuth
  └─ API Key：[输入框]
工具勾选         ☑ 工具A    ☑ 工具B    ☑ 工具C
                 （仅展示此账号有权调用的工具；
                   无权调用的工具不显示）
─────────────────────────────────────────────
```

关键规则：
- 工具列表从 MCP server 动态拉取，仅展示当前账号实际有权调用的工具
- 无权调用的工具**不显示**，不展示为置灰或禁用状态
- 默认全选；用户可取消勾选不需要的工具

---

**③ Database（数据库查询）**

用于让数字员工读写企业数据库。

```
接入类型：Database
─────────────────────────────────────────────
数据库类型       [MySQL / PostgreSQL / 其他]
连接地址         [host:port]
数据库名         [database name]
账号             [username]
密码             [password，输入后隐藏显示]

可访问的表       ┌──────────────────────────────┐
（只读展示）      │ ✓ orders         read         │
                 │ ✓ customers      read/write    │
                 │ ✓ products       read         │
                 └──────────────────────────────┘
                 表权限由数据库账号的实际授权决定，
                 平台仅做展示，不支持在此修改权限。
─────────────────────────────────────────────
```

关键规则：
- 填写连接信息并验证通过后，平台自动拉取该账号可访问的表及其读写权限
- 权限列表为只读展示，不可在平台侧勾选或修改——表的实际访问权限由数据库账号决定
- 连接验证失败时，提示"连接失败，请检查地址和账号信息"，不展示空表列表

---

**④ RAG（知识库检索）**

用于为数字员工挂载运行时可检索的文件知识库。

```
接入类型：RAG
─────────────────────────────────────────────
知识库名称       [填写，用于区分多个知识库]
文件上传         [拖拽或点击上传，支持 PDF / DOCX / TXT / MD]
                 ┌─────────────────────────────────────────┐
                 │  这里上传的文件用于运行时检索，不是员工背景知识  │
                 └─────────────────────────────────────────┘
已上传文件        合同模板v3.pdf          [删除]
                 产品手册2024.docx       [删除]
检索策略         ○ 语义检索  ○ 关键词检索  ○ 混合检索
─────────────────────────────────────────────
```

关键规则：
- 提示文字"这里上传的文件用于运行时检索，不是员工背景知识"始终展示在上传区域上方，不可关闭
- 本区域上传的文件进入运行时检索索引，与会话框上传的知识文档（影响本体抽取）严格区分
- 支持上传多个文件，每个文件独立显示上传状态（解析中 / 已就绪 / 解析失败）
- 一个外部对接条目可挂载多个 RAG 知识库，每个知识库独立配置

---

**无外部系统的处理：**
- 提供"此员工无需对接外部系统"勾选项
- 勾选后③阶段标记为"已跳过"（绿色跳过标签），不阻塞④阶段。

**阶段推进条件：** 至少一条外部系统已完成，或标记为"跳过"，自动解锁④阶段。

---

##### 待办区 · 阶段④：生成实例包

**外观：** 右侧面板底部展示"生成实例包"大按钮。

**触发条件（硬性校验，不满足则按钮置灰）：**
- ①②③三阶段的所有必要待办均已完成（`100%`）

**生成中状态：**
- 按钮变为"生成中…"+ 进度动效
- 提示文字："正在汇总三阶段产物，测试用例自动打包（预计 10-30 秒）"

**生成完成：**
- 提示"实例包已生成，即将进入 AI 评估"
- 跳转到 AI 评估页

---

#### 4.6.5 保存与恢复机制

- 任意时刻点击"保存退出"，当前会话历史、待办状态、已上传文件全部持久化保存
- 再次从部门员工列表点击"继续雇佣"，进入同一个会话窗口和沙箱，状态自动恢复
- 一个雇佣任务**对应唯一一个会话窗口**，不能新建第二个窗口

- **进入条件：** AI 评估通过后点击"进入人工评估"；或从待实习列表直接进入

### 4.11 分身复制向导（三步）

- **页面目标：** 以最少步骤帮助用户从部门员工快照复制出一个上岗的个人分身。
- **适用角色：** 部门长、普通成员
- **进入条件：** 从部门员工详情页 / 列表卡片点击"创建分身"

---

#### 4.11.1 向导总览

```
步骤条：① 确认复制  →  ② 设置显示信息  →  ③ 完成上岗
```

**目标：点击"创建分身"到完成上岗，用户操作步骤不超过 3 步，平台侧 P95 ≤ 30 秒。**

---

#### 步骤一：确认复制

**页面内容：**

- 来源员工信息：名称、头像、来源模板、能力简介
- 说明文字："创建分身后，你将获得这个员工的完整副本，独立运行，不受原员工升级影响"
- [确认创建分身]主按钮

---

#### 步骤二：设置显示信息

**页面内容：**

- `display_name`（必填）：分身的平台显示名，同一用户下不能重名
- `display_avatar`（可选）：默认沿用部门员工头像，可上传自定义头像
- `display_description`（可选）：个人简介

---

#### 步骤三：完成上岗

**页面内容：**

- 动效：员工头像 + "上岗成功！"
- 说明文字：
  - "站内对话已可使用，点击下方按钮立即开始"
  - "如需在飞书/钉钉/企微中使用，可在员工卡片上配置 IM"
- [立即开始对话] 主按钮（进入站内对话页）
- [去配置 IM] 次要按钮（可选）
- [返回我的数字员工] 次要链接

**关键规则：**

1. 分身复制成功后，员工状态直接为 `live`，不需要评估。
2. IM 配置为可选操作，不阻塞上岗。
3. 分身数量达到上限时（10个），步骤一展示禁用状态和提示："已达分身上限（10/10），请退役不再使用的分身后重试"。

### 4.12 私有分支定制页

- **页面目标：** 在已有个人分身基础上，通过雇佣教练简化模式进行个性化定制，经双阶段评估后上岗。
- **适用角色：** 分身 owner
- **进入条件：** 从"我的分身"详情页点击"创建私有分支"

#### 4.12.1 整体布局

布局与部门版雇佣页相同（左侧会话区 + 右侧待办区），但有以下差异：

| 差异项 | 部门版雇佣 | 私有分支定制 |
|---|---|---|
| 右侧初始内容 | 空（等待装配） | **预载父分身的①②③三阶段产物** |
| 会话开场 | 介绍自己，引导上传资料 | 告知已预载的产物，询问想修改什么 |
| 阶段解锁 | 按序逐一解锁 | 全部阶段直接解锁（可直接定位修改） |
| 评估者 | 部门长 | **分身 owner 自己** |

**预载产物说明：**

- ① 上传资料：显示父分身的本体切片摘要（不是原始文件），提供"查看摘要"按钮
- ② 补齐技能：显示父分身的 Skill 列表（可修改、可新增）
- ③ 配置外部系统：显示父分身的外部系统配置（可修改、可新增）

---

#### 4.12.2 定制流程

1. 雇佣教练以简化模式开场："我已预加载了你的分身配置，你想修改哪部分？"
2. 用户描述修改意图（如"我想增加一个处理退款的技能"）
3. 雇佣教练定位到对应阶段，引导针对性修改，修改完毕后触发对应子技能重新执行
4. 未触及的阶段保持原产物不变
5. 修改完成后，手动点击"生成新实例包"，进入 AI 评估

## 6. 交互规则汇总

### 6.1 导航与返回

1. 雇佣流程页中"返回"操作触发"保存确认弹窗"，提示"进度已自动保存，可随时返回继续"
2. AI 评估进行中可安全离开，评估后台继续，不丢失进度
3. 站内对话页返回后历史保留，再次进入继续上次对话

### 6.2 分身数量上限

1. 同一用户下非 `retired` 状态的分身总数上限 **10 个**（含所有部门员工的分身合计）
2. 达到上限时：
   - "创建分身"按钮置灰
   - 提示："已达分身上限（10/10），请退役不再使用的分身后重试"
3. `retired` 状态的分身不计入上限

### 6.3 快照独立性说明

1. 分身创建成功后，展示说明："你的分身已独立运行，后续母版升级不会自动更新到你的分身"
2. 此说明在首次创建分身时以引导提示展示，后续不重复显示

### 6.4 凭证安全展示

1. 所有 IM 凭证字段（App Secret、Encrypt Key 等）在展示时统一遮蔽（`••••••••`）
2. 提供眼睛图标切换显示/隐藏
3. 凭证回填时仅允许输入框为焦点时显示明文，失焦后自动遮蔽

### 6.5 错误与异常处理

1. IM 连接失败：展示具体失败原因（如凭证无效、网络超时）并提供重试入口
2. 沙箱异常（error 状态）：卡片显示红色异常标签，站内对话页展示 banner 提示，不阻塞其他员工
3. 快照复制失败：弹出错误提示并提供"立即重试"按钮，不消耗分身数量上限
4. 连续评估失败 3 次：报告页面顶部展示提示建议，不强制限流

### 6.6 站内对话与 IM 渠道的区分展示

1. 在员工详情页的运行状态区，分别展示：
   - 站内对话：最近活跃时间、累计对话轮次
   - IM 渠道（各平台）：最近消息时间（不展示具体内容）
2. 两个渠道的历史记录在界面上明确区分，不混用
